# The shared rules come from charter 3.3.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `dev-kit` 1.2.1 dev dependency with `charter` 3.3.0, load the shared rules by module, and leave no living document naming the old kit.

**Architecture:** One commit swaps the kit and everything that points into it — dependency, Prettier key, both tsconfigs, `./run`'s bootstrap, the two tests that read kit files, `CLAUDE.md`'s import — and runs `charter init`, so no commit leaves a session importing from a directory that is gone. `./run`'s frame then gains the kit's plugin and hook installers. The last task rewrites the living documents and records the two out-of-scope findings.

**Tech Stack:** charter 3.3.0 (git dependency), Bash (`./run`), Vitest, Prettier 3.

**Spec:** [docs/superpowers/specs/2026-10-17-charter-design.md](../specs/2026-10-17-charter-design.md)

## Global Constraints

- Dependency: `"charter": "github:AlexeyVanyukevich/charter#v3.3.0"` in `devDependencies`; `dev-kit` gone from `package.json` and `package-lock.json`.
- Modules: `npx --no charter init backend typescript node vitest`, at the root, once. No `--workspace`.
- `"prettier": "charter/stacks/typescript/prettier"`; both tsconfigs `"extends": "charter/stacks/node/tsconfig"`.
- `./run`: `node_modules/charter/core/lib.sh` in the bootstrap test and the `source` line; `CHARTER_NODE_HINT`, not `DEVKIT_NODE_HINT`.
- `.claude/settings.json` is committed as `init` leaves it, with the existing `superpowers` entry. `.claude/rules/charter/` is never committed.
- Commits: `type(scope): subject`, ≤ 72 characters, **subject only — no body, no trailer**. From Task 2 on, the kit's `commit-msg` hook enforces this.
- Before every commit: `git branch --show-current` prints `build/charter`, and `./run check` passes. If `helper.test.ts` fails on containers labelled `booking-engine-testing=true` that this run did not start (`docker ps --filter label=booking-engine-testing=true`), another project's suite is running: wait for it and re-run.
- A single test file runs with `npx vitest run <path>`.

## Review Focus

1. **An import in `CLAUDE.md` that names a missing file loads nothing, silently** — the session just lacks the rules. Task 2's `every import in CLAUDE.md names a file that exists`.
2. **A clone where `npm install` has not run** must get the hook's instruction, not a Node stack trace. Task 2, Step 8: the hook command under an empty `CLAUDE_PROJECT_DIR`.
3. **A bad commit subject is refused** once the hook is in. Task 2, Step 9.
4. **CI has no Claude Code:** `need_plugins` must note the skip and return zero, or the release workflow's `./run check` fails. Task 3, Step 6.
5. **The shared http table still parses** now that `http.md` opens with a `paths:` frontmatter, so the departure test keeps meaning something. Task 2, Step 7, `documented-tables.test.ts`.

- [ ] **Step 4: Record the two out-of-scope findings**

At the top of `docs/backlog.md`, newest first, two entries in the file's format, both `Found: 2026-10-17, while moving the shared rules to charter`:

- **The key console is not held to the frontend accessibility rules.** Where: `charter.json`, no `frontend` or `playwright` module; `tests/ui/`. Problem: the `typescript`, `node` and `vitest` stacks ship oxlint configs that catch unhandled promises and non-exhaustive switches, and nothing here runs them. Impact: those bugs reach review uncaught; the kit measured 36–78 findings on adoption in three projects, so adopting is a slice with triage.
