# Adopting dev-kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the engine a consumer of every `dev-kit` module and rule, with no change to the engine's behaviour.

**Architecture:** `dev-kit` is a dev dependency installed over git at a pinned tag. `tsconfig.json` extends its Node base, `package.json` points Prettier at it, `./run` sources its shell library after a bootstrap, and a new `CLAUDE.md` imports its nine rules. `docs/conventions.md` stays as the engine's local rules, trimmed of what the kit now states.

**Tech Stack:** Node 24, TypeScript 7 (`tsc`), Prettier 3, bash, Docker Compose, Vitest + Testcontainers.

**Spec:** [docs/superpowers/specs/2026-10-01-adopt-dev-kit-design.md](../specs/2026-10-01-adopt-dev-kit-design.md)

## Global Constraints

- Install line, verbatim: `"dev-kit": "github:AlexeyVanyukevich/dev-kit#v1.2.1"` in `devDependencies`. No `.npmrc`.
- `exactOptionalPropertyTypes` stays on. A type error is fixed at its call site or by widening a type to `| undefined`, never by overriding the flag.
- No endpoint, schema, migration, response body or `./run` scenario changes behaviour.
- `openapi.json` must regenerate byte-identical.
- Commit messages are a single Conventional Commits subject line: no body, no footers, no `Co-Authored-By` trailer.
- Work stays on `build/adopt-dev-kit`, which is merged by rebase.
- Every commit passes `./run check`, which needs Docker running.
- Documents refer to other projects by role ("the admin consumer"), never by directory name. Exceptions are names that are load-bearing: `dev-kit`, the GitHub specifier, file paths.

## Review Focus

1. **An existing checkout whose `node_modules` predates the kit.** `./run` must install the kit and then work. A test for the directory instead of the file would skip the install, and `source` would then fail. Tested in Task 2, Step 9.
2. **First run with no `.env`, under `set -e`.** The kit's `need_env` returns 1 after creating `.env`, so a bare call ends the script silently. The scenario must continue and print the `DATABASE_URL` note. Tested in Task 2, Step 10.
3. **A port on the command line beats a port in `.env`.** The kit's `load_env_file` replaces the local one, so the precedence must be unchanged. Tested in Task 2, Step 8 by diffing the two function bodies.
4. **The Docker build stage on Alpine, which has no git.** `npm ci` must still fetch a `github:` dependency, and the runtime image must not contain the kit. Tested in Task 5, Step 2.
5. **Compiled output under `target: ES2023`.** The built server must still start and answer. `tsc --noEmit` does not prove that. Tested in Task 5, Step 3 with `./run up` and `./run smoke`.

load_env_file

CONSOLE_PORT="${CONSOLE_PORT:-3001}"
DB_HOST_PORT=5433

RUN_STATE=".run"
COMPOSE_DB_URL="postgres://postgres:postgres@localhost:${DB_HOST_PORT}/booking_engine"

# Read by the kit's `need_node`: the floor is its default of 24, the pointer to `.nvmrc` is ours.
DEVKIT_NODE_HINT="Install Node 24 or newer — see .nvmrc."

# ── preflight ────────────────────────────────────────────────────────────────

# The kit's need_env creates .env and reports that it did; what the new file already points at

need_local_env() {

}
